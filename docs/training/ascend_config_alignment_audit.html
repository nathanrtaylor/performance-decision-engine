ASCEND Config Alignment Audit

A working agenda for reconciling the training program structure with the skills & scoring catalog — so every simulator and CBT an expert practices resolves to a learning block and a scorable skill.

01

Purpose & participants

Today the training dashboard silently drops activity it can't attribute. A tester can run the Block 3 simulators all week and see a blank block, because the config that describes the program and the config that describes scoring don't reference each other consistently. This audit closes that gap with the people who own the source content.

Content team

Owns the simulator IDs & personas, which skills each block is meant to teach, and the gate test-calls. The audit needs their answers to link sims to blocks and blocks to skills.

Analytics

Owns the skill catalog, the behavior→skill mapping, and the pipeline. Applies the decisions to the YAML, regenerates configs, and verifies the numbers moved.

The single goal: every simulator/CBT an expert practices → resolves to a block → rolls up into scorable skills → shows on the dashboard.

02

How the two files connect

training_program.yaml owns structure — the 16 learning blocks, their order, gates, and the components (which sims/CBTs belong to each block). training_profiles.yaml owns skills & scoring — the skill catalog and the 124 simulator profiles that say which skills each sim evaluates. No code reads both files together; they meet only through a shared skill-id namespace.

Walk these in order during the audit. Each names the decision to make, who owns it, and how we'll know it's done.

WI-1Highest leverageContent + Analytics

Persona ↔ live challenge_id crosswalk

Issue
The program's sim IDs (ASC-SIM-…) and personas don't match the live simulator challenge_id seen in the data (scorecard_name). Overlap is 0/100, so 90 personas can't map to a scorable profile.
Decide
For each sim in scope, the live challenge_id that corresponds to its ASC-SIM ref + persona.
Source
Content team holds the SIM design registry; Analytics supplies the live challenge_ids from the extract.
Done-when
A committed crosswalk table covers the personas in scope; ref↔challenge_id overlap > 0 and rising.

Block develops: completeness

Issue
5 blocks have components but an empty develops: [], so they can never show skill progress — this is exactly why Block 3 renders blank even after its personas matched.
Decide
Which skills each of the 16 blocks actually teaches — starting with the 5 empties (03, 04, 05, 07, 16).
Source
Content team (curriculum intent).
Done-when
check_training_program.py reports no develops_unknown errors and no unexpectedly-empty blocks; Block 3 renders skills for a known tester.

Issue

Source
Analytics (catalog) with content-team confirmation of intent.
Done-when
Every behavior a scoped sim emits maps to a skill; the rollup drops ~0 rows for those sims.

05

Audit workflow

Before

Prepare

  1. Circulate this doc + the appendix worksheets.
  2. Content team pre-fills any persona→challenge_id mappings they already know.
  3. Analytics exports the live challenge_ids + unmapped behaviors from the latest extract.
During

Decide & log

  1. Walk WI-1 → WI-5 in order.
  2. Log every decision (persona→challenge_id, block→skills) in a shared sheet as you go.
  3. Any unknown becomes an action with an owner and a due date — don't block the room.
After

Apply & confirm

  1. Analytics applies decisions to the YAMLs and regenerates configs.
  2. Re-run verification (section 06).
  3. Send the refreshed snapshot back so the team sees the numbers move.
06

Verification & sign-off

The loop that proves an alignment decision actually took effect.

  • Regenerate mappings — python tools/gen_training_configs.py
  • Structure check passes — python -m pde.cli.check_training_program reports no new develops_unknown errors
  • Rebuild skills + run pipeline — build_training_assist_skills → run_training_pipeline
  • Confirm attribution — a known tester's audited sim activity now attaches to the intended block in training_dashboard.json
  • Sign-off: agreed snapshot targets met — ref↔challenge_id overlap, empty-develops count, and unmapped-behavior count all at target
